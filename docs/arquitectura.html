Carril

Gestor de tareas tipo Kanban: tableros con columnas (Por hacer, En curso, Hecho…) y tarjetas que se arrastran entre ellas. Este documento define cómo se reparten los servicios, los proyectos, las pruebas y los agentes antes de escribir código.

Angular 19FastAPI · Python 3.12PostgreSQL 16Docker Compose
Servicios

Cómo se conectan las piezas

La API y la base de datos corren en Docker Compose. El frontend corre fuera de Docker con ng serve y reenvía las llamadas /api a la API mediante un proxy de desarrollo, así el navegador no necesita CORS en local.

Puertos y credenciales salen de .env (plantilla en .env.example). docker compose up -d levanta db y luego api, que espera al healthcheck de Postgres.

Proyectos

Tres carpetas, un agente por carpeta

database/

PostgreSQL 16 · SQL plano · pytest + psycopg
  • DDL numerado y reejecutable (IF NOT EXISTS)
  • Restricciones, índices y trigger de updated_at
  • Datos de ejemplo separados del esquema
  • Diccionario de datos y diagrama ER

backend/

Python 3.12 · FastAPI · SQLAlchemy 2 · Pydantic v2 · pytest
  • Capas: routers → services → repositories
  • Autenticación JWT con contraseñas bcrypt
  • Reordenamiento de columnas y tarjetas en transacción
  • Dockerfile multi-stage, usuario no root

frontend/

Angular 19 standalone · signals · SCSS · Playwright
  • Sin librerías de UI: componentes propios
  • Drag & drop con la API nativa de HTML5
  • Interceptor JWT, guard de rutas y manejo de errores
  • Login, lista de tableros, vista de tablero, detalle de tarjeta

Modelo de datos

Siete tablas

Llaves primarias UUID (gen_random_uuid()). El orden de columnas y tarjetas se guarda en position (entero); al mover una tarjeta, la API corre las posiciones de su columna origen y destino en una sola transacción.

  labels { uuid id PK
    uuid board_id FK
    text name
    text color }
  task_labels { uuid task_id PK
    uuid label_id PK }
  task_comments { uuid id PK
    uuid task_id FK
    uuid author_id FK
    text body }

task_priority: low · medium · high · urgent. Borrar un tablero borra en cascada columnas, tarjetas, etiquetas y comentarios. wip_limit es opcional y el frontend lo marca cuando una columna lo supera.

Contrato de la API

Endpoints /api/v1

Todo excepto registro, login y /health exige Authorization: Bearer <jwt>. Cada usuario solo ve sus tableros; un recurso ajeno responde 404.

Ejecución

Orquestación de agentes

Yo actúo como orquestador: fijo el contrato (este documento, el DDL de referencia y la tabla de endpoints) y le entrego a cada agente una tarea cerrada sobre su carpeta. Ningún agente toca la carpeta de otro.

Fase 0 orquestador · opus 5.5

Contrato

Compose, .env.example, README raíz y los briefs de cada agente.

Fase 1 sonnet 5.5

Agente database

DDL, seed, pruebas y docs. Debe pasar sus pruebas en el Postgres de Compose.

Fase 2 · en paralelo sonnet 5.5 × 2

Agentes backend y frontend

Backend sobre el DDL real; frontend sobre el contrato de la API. Al terminar, corro el e2e del frontend contra la API real.

Fase 3 opus 5.5

Agente validador

Levanta todo desde cero, corre las tres suites de cada proyecto, revisa contrato, seguridad y docs, y entrega un informe. Los fallos vuelven al agente dueño.

Decisiones que tomé

  • “Tipo canva”Lo interpreté como tablero Kanban (columnas y tarjetas arrastrables). Si te referías a otra cosa, dime.
  • Angular 19Tu Node es 20.12.2; Angular 20 exige Node 20.19 o superior. Con Angular 19 no tienes que actualizar nada. El CLI se usa vía npx.
  • “Angular puro”Sin Angular Material, CDK, PrimeNG ni Tailwind. Estilos SCSS propios y drag & drop nativo.
  • Esquema en SQLEl esquema vive solo en database/ddl; el backend no usa Alembic ni create_all, solo mapea las tablas.
  • UsuariosCada usuario tiene sus propios tableros (sin compartir tableros entre usuarios en esta versión).
